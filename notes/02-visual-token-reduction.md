# ② 视觉 Token 削减（Multimodal Prefill）

## 1. 瓶颈从哪来

以 LLaVA-1.5 为代表的视觉问答模型：

```
图片 → CLIP ViT（如 ViT-L/14@336）→ 576 个 patch token
                                    → MLP projector → 接进 LLM 的序列
```

- 一张图产生 **576 个视觉 token**，和文字 token 一起进入 prefill；
- 自注意力成本约随序列长度二次增长，且生成全程都要带着这些 KV；
- 经验事实：大量 patch 是冗余背景（天空、墙面、重复纹理），真正承载答案的往往是少数区域。

## 2. 公开方法路线

| 方法 | 思路 |
|---|---|
| FastV | 观察到浅层视觉 token 注意力里有"剪枝友好"信号，直接按分数丢 token |
| VisionZip | 选取显著（dominant）+ 上下文（context）两类视觉 token，在质量/速度间取平衡 |
| Token 合并类 | 把相似 patch 表示合并，而不是硬删 |
| 学习型选择器 | 训练一个小选择网络（代价是额外训练） |

## 3. 设计一个视觉 token 任务时必须想清楚的事

1. **选择发生在哪一层**：CLIP 输出处，还是语言模型中间层？早丢便宜但信息少，晚丢贵但判断准；
2. **可改面**：只给选择函数（输入 hidden states / 注意力，输出保留特征与索引），模型、权重、prompt、解码全部冻结；
3. **双指标 + 硬门**：
   - 质量 Q：多基准平均（如 POPE 三种幻觉拆分 random/popular/adversarial + TextVQA 的多人答案软分）；
   - 耗时 T：可信父进程测完整墙钟（含加载、处理、生成），候选自报时间不算数；
   - 门：Q 不得低于基线的 95%，且每一单项不得低于 90%，无效率设上限；
4. **防作弊沙箱**：选择函数运行在受限命名空间（禁文件/网络/私有名访问/改权重），源码大小受限；
5. **Public/Private 隔离**：公开集只能用于选 best，最终私有集一次性验收，不反馈逐题结果。

## 4. 典型失败模式（重要教训）

- 一个在 512 题 Public 上质量几乎不掉、成本降 18% 的固定策略，**换另一个 512 题 Private 就可能掉 9+ 个百分点**；
- 同一冻结模型把 Public 重跑两次、方差为 0，**对泛化没有任何保证**——那只是确定性重复评测；
- 原因：固定策略容易过拟合公开集的题型/答案分布（例如学到与某类问题虚假相关的 patch 模式）。
