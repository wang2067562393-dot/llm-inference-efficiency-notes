# ③ 投机解码（Speculative Decoding）与 EAGLE

## 1. Decode 阶段为什么慢

batch=1 自回归生成时，每生成一个 token 都要把全部模型权重从显存读一遍，计算密度很低，**瓶颈是显存带宽而不是算力**。GPU 大量算力闲置——如果能一次前向"顺带"验证多个候选 token，就可能用同样的访存代价多拿几个 token。

## 2. 基本算法

1. 草稿模型（小、快）一次猜出 k 个未来 token；
2. 目标模型（大、慢）**一次前向**并行验证这 k 个 token；
3. 接受最长匹配前缀，第一个不匹配位置用目标模型自己的分布采样/argmax 纠正；
4. 接受长度越长，单 token 摊销成本越低。

**关键权衡**：草稿生成本身有成本。猜得太宽/太深、命中率低时，反而比直接 decode 更慢。期望接受长度（accept length）是核心中介指标，但它不能直接等同墙钟收益，必须配对实测延迟。

## 3. 公开代表方法

| 方法 | 草稿来源 | 特点 |
|---|---|---|
| 原始投机解码（Leviathan 2023 / Chen 2023） | 独立小模型 | 理论上无损（同分布采样时） |
| Medusa | 目标模型自己加多个解码头 | 无需独立草稿模型，树状候选 |
| Lookahead | n-gram 猜测 | 无需额外模型，纯推理期技巧 |
| EAGLE | 在目标模型**隐藏状态层**训练草稿头 | 接受长度显著更高 |
| EAGLE-2 | 动态草稿树 | 根据置信度调整候选结构 |
| EAGLE-3 | 动态草稿深度 + 多尺度特征 | 该深则深、该浅则浅 |

## 4. 动态草稿深度为什么重要

- 高置信、模式化文本（列表、代码、固定格式）：深草稿命中率高，值得多猜；
- 语义转折点、低置信位置：深草稿几乎全 miss，纯浪费一次小模型前向；
- 运行时可用的廉价信号：`proposed`（上轮深度）、`accepted`（命中数）、`produced`（已生成长度）、`remaining`（距上限）、`miss_streak`（连续未命中）；
- 一个常见反直觉发现：**"请求内历史片段复用"在很多真实分布上收益接近零**——n-gram 续写看起来合理，但经验上触发后质量风险大、延迟收益小，必须让实验证伪，不能凭直觉保留。

## 5. 评测协议要点

- 主指标用 **ms/token（总正式请求秒数 ×1000 / 完整生成 token 数）**，不是总延迟（生成长度不同会污染比较）；
- **配对设计**：同一批请求、相邻时间、同一 slot 跑 baseline 与候选，消除机器漂移；
- 质量保真门：逐请求对比 token IDs / 答案文本，统计差异率（如 ≤5% 严档、≤10% 宽档），核输入哈希、finish_reason、输出上限；
- 诊断短测（少量题）必须打 `diagnostic_only`，不能当成绩；
- 接口设计教训：如果正式接口把策略限制成无状态标量函数（看不到 token 内容、不能持有索引），而 reference 的收益来自有状态的历史续写，**两者可达的方法空间根本不同**，分数差距不能简单归因于"agent 能力差"。评审一个 benchmark，先审 action space 与 reference 的匹配性。
